Legalean

Turns statutory excerpts into deontic-logic rules and proves conflicts between them with the Lean 4 kernel — a machine-checked proof term, not a heuristic match.

Source on GitHub CI status The corpus

What it does

Two statutes can be read for years before anyone notices they cannot both be obeyed. Legalean takes hand-formalized statutory rules, finds pairs that are structurally plausible contradictions, generates a Lean 4 theorem claiming False from the two rules together, and reports the pair only if Lean's kernel accepts the proof.

The guarantee is deliberately narrow: Lean verifies that the formalized rules are logically inconsistent. It never verifies that the formalization is faithful to the statute — that part is human work, and each corpus file records where it compresses real doctrine.

The verification pipeline is stdlib-only Python plus Lean. No API key, no network access, no third-party Python packages.

Pipeline

01CorpusOne markdown file per excerpt; formalization in frontmatter, reasoning below it.
02Pre-filterPure Python. Overlapping scopes, same activity, contradictory actions, a constructible witness.
03CodegenOne self-contained Lean theorem per candidate pair.
04KernelCompiled with lake env lean. The compiler, not Python, returns the verdict.

The pre-filter does not decide whether two rules conflict — it decides which pairs are worth asking Lean about. If its witness does not really satisfy both conditions, Lean rejects the file and the pair is dropped.

The axioms

A tiny axiom set, not a large proof library. The modalities are opaque; the only facts Lean knows are the two exclusions:

axiom Allowed : Prop → Prop
axiom Prohibited : Prop → Prop
axiom Required : Prop → Prop

axiom allowed_prohibited_excl (p : Prop) : Allowed p → Prohibited p → False
axiom prohibited_required_excl (p : Prop) : Prohibited p → Required p → False

allowed/required is deliberately not exclusive — a mandatory act is trivially a permitted one — and two real pairs in the corpus depend on exactly that choice.

A generated proof

theorem conflict_us_ina_employment_noncriminalization_vs_az_sb1070_5c
    (ruleA : (∀ x : Int, True → Allowed (Activity x)))
    (ruleB : (∀ x : Int, True → Prohibited (Activity x))) :
    False :=
  allowed_prohibited_excl (Activity 0) (ruleA 0 trivial) (ruleB 0 trivial)

Numeric conditions such as age >= 18 discharge with core Lean's omega decision procedure instead of trivial — no mathlib, just Lean 4 core.

Results on real law

The corpus covers federal immigration law against Arizona's S.B. 1070, the 2010 enforcement law partly struck down in Arizona v. United States, 567 U.S. 387 (2012). Twelve excerpts, chosen so every branch of the logic is exercised against actual statutes with known outcomes.

The last two rows are the honest part. Both provisions were struck down, and the tool correctly reports nothing about them: each merely duplicates the federal prohibition, so there is no logical contradiction to find. The defect is that Congress occupied the field. That needs a different rule field and new axioms — left unmodeled deliberately rather than modeled inaccurately, and kept in the corpus rather than hidden.

Limitations

  • Formalization is the weak link, and it is manual. Lean checks the formalized rules, never their fidelity to the statute. Each file's formalization notes record what it compresses.
  • Field and obstacle preemption are not modeled — two documented false negatives, above.
  • Single-variable conditions only. age >= 18 works; compound conditions and disjunctions do not, and are excluded from candidates rather than guessed at.
  • Scope overlap is a hardcoded lookup, not real jurisdiction law. It knows only the jurisdictions in the corpus.
  • Small, curated corpus. Twelve excerpts. Not a survey of immigration law.
  • Not legal advice. "Formally verified" is a much narrower claim than "these statutes conflict as a matter of law." The tool knows nothing of severability, amendment, repeal, standing, or remedy.

Running it

Python 3.10+ and the Lean 4 toolchain (elan, providing lean/lake). No pip install is needed for the verification path.

git clone https://github.com/mehdievaltimes/legalean
cd legalean
python3 check_conflicts.py

Expected output: 12 rules loaded, 2 candidates checked, 2 formally verified conflicts. CI runs exactly this on every push, so the build badge reflects proofs that actually compile on a clean machine.
