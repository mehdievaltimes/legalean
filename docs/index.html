Legalean

Formalizes statutes as deontic-logic rules and proves the conflicts between them with the Lean 4 kernel. Every reported conflict carries a proof term a compiler type-checked — not a heuristic match, and not a Python assertion about one.

What it does

Two statutes can be read for years before anyone works out that they cannot both be obeyed. Legalean takes hand-formalized statutory rules, finds pairs that are structurally plausible conflicts, generates a Lean 4 theorem deriving False from the two rules together, and reports the pair only if Lean's kernel accepts the proof.

The guarantee is deliberately narrow. Lean verifies that the formalized rules are inconsistent; it never verifies that the formalization is faithful to the statute. That part is human work, and every corpus file writes down where it compresses real doctrine.

The verification pipeline is stdlib-only Python plus Lean — no API key, no network access, no third-party Python packages, and no mathlib.

Two kinds of conflict

Most tools in this space look for direct contradiction. That misses the doctrine that actually decided several of these cases, so the tool models both:

Contradiction

One sovereign permits an act the other forbids, for a case both rules cover. The classic conflict — and it requires the two rules to genuinely disagree.

6 of 12 · closes with allowed_prohibited_excl or prohibited_required_excl

Field preemption

A field belongs exclusively to one sovereign, so any rule from another sovereign in that field collides with it — even one that agrees word for word.

6 of 12 · closes with field_preemption_excl

The second kind is why the corpus can handle S.B. 1070 § 3 and Ala. H.B. 56 § 10. Both merely duplicate the federal prohibition — both rules say prohibited, they agree completely — and both were struck down anyway, because Congress occupied the field. Alabama's § 10 is defined by reference to violations of the federal sections it mirrors; the Eleventh Circuit held it preempted regardless, since even complementary state regulation is impermissible there.

A single exclusive: true flag on one federal rule displaces parallel offences in two states at once. Three fields are occupied in the corpus — alien registration, alien harboring and fraudulent immigration documents — each by a different federal rule, so the mechanism is not special-cased to one provision. The harboring field alone displaces parallel offences in three states, and S.C. Act 69 is displaced twice over, by two different fields.

Arizona's A.R.S. § 13-2929 is caught twice, on independent grounds: displaced by the federal harboring field claim, and separately contradicting the federal religious safe harbor. That is how the Ninth Circuit decided it — field preempted and conflict preempted, in consecutive sections of the same opinion.

Pipeline

01CorpusOne markdown file per excerpt. Formalization in frontmatter, reasoning written out below it.
02Pre-filterPure Python. Same activity, a constructible witness, then either contradictory actions or an exclusive field claim.
03CodegenOne self-contained Lean theorem per candidate. Carrier type and closing axiom follow the pair.
04KernelCompiled with lake env lean. The compiler returns the verdict, not Python.

The pre-filter does not decide whether two rules conflict — it decides which pairs are worth asking Lean about. If the witness it computes does not really satisfy both conditions, Lean rejects the file and the pair is dropped. A test pins that behaviour with a deliberately non-overlapping witness, so the guarantee is load-bearing rather than decorative.

The Lean side

A tiny axiom set, not a large proof library. The modalities are opaque; these are the only facts Lean is given:

axiom Allowed : Prop → Prop
axiom Prohibited : Prop → Prop
axiom Required : Prop → Prop

axiom allowed_prohibited_excl (p : Prop) : Allowed p → Prohibited p → False
axiom prohibited_required_excl (p : Prop) : Prohibited p → Required p → False

axiom ExclusivelyFederal : Prop → Prop
axiom field_preemption_excl (p : Prop) :
    ExclusivelyFederal p → (Allowed p ∨ Prohibited p ∨ Required p) → False

allowed/required is deliberately not exclusive — a mandatory act is trivially a permitted one — which is why the E-Verify and § 2(B) pairs stay correctly silent. Put together, the corpus says a state may require what federal law merely permits, but not what it forbids.

A contradiction, with a real numeric side condition

Tex. Educ. Code § 21.031 carried its own school-age floor, so the Plyler pair exercises arithmetic on actual law. Numeric conditions discharge with core Lean's omega:

theorem conflict_us_const_equal_protection_education_vs_tx_educ_code_21_031
    (ruleA : (∀ x : Int, x > 5 → Allowed (Activity x)))
    (ruleB : (∀ x : Int, True → Prohibited (Activity x))) :
    False :=
  allowed_prohibited_excl (Activity 6) (ruleA 6 (by omega)) (ruleB 6 trivial)

6 is the witness the Python pre-filter computed for age > 5. Lean re-derives that it satisfies the premise rather than taking Python's word for it.

A field preemption

The displaced rule is stated with its actual modality and injected into the disjunction, so the theorem is about the real rule rather than a paraphrase:

theorem preemption_us_ina_alien_registration_vs_az_sb1070_3
    (federal : (∀ x : Int, x ≥ 18 → ExclusivelyFederal (Activity x)))
    (state : (∀ x : Int, True → Prohibited (Activity x))) :
    False :=
  field_preemption_excl (Activity 18) (federal 18 (by omega))
    (Or.inr (Or.inl (state 18 trivial)))

Both rules there say prohibited. They agree, and it is still a conflict. Two things keep this from over-firing: the federal rule's own condition must hold at the witness, and the scope relation must be strict — so a sovereign never preempts itself, and no state preempts another.

Categorical conditions

Boolean and string conditions quantify over Bool or String and discharge with decide, still core Lean. This is what lets the federal harboring safe harbor be formalized as religious_volunteer == true. The carrier type is fixed by the witness, so a variable given a number on one side and a string on the other yields no candidate rather than a bogus one.

Where the boundary is

What "formally verified" does and does not cover here, stated plainly:

  • exclusive: true is a judicial holding, not statutory text — the most editorial input in the corpus. Every other frontmatter field is read off the excerpt. Congress does not write "we occupy this field"; courts infer it. So marking a rule exclusive feeds a legal conclusion in and derives consequences from it. The derivation is machine-checked; the premise is a judgment call, and a wrong one propagates silently.
  • Jurisdiction is not formalized in Lean. The modalities carry no scope, so nothing in the Lean encoding knows federal law outranks state law. Python decides which pairs are eligible before a theorem is generated. Lean verifies the deontic and arithmetic core; Python supplies the jurisdictional premises.
  • Constitutional rules fit the schema worst. Plyler's rule is a standard applied to a state's justification, not a flat ban. Encoding it as an unconditional prohibited drops that escape hatch and makes the rule look more absolute than it is.
  • Formalization is manual, and it is the weak link. Lean checks the formalized rules, never their fidelity to the statute. Each file's formalization notes record what it compresses — read them skeptically.
  • Only field preemption is modeled, not conflict or obstacle preemption as doctrines. Those surface here only where they coincide with a deontic contradiction, as with the harboring pair.
  • Single-variable conditions only. Compound conditions and disjunctions are excluded from candidates rather than guessed at.
  • Not legal advice. "These two formalized rules are logically inconsistent" is a much narrower claim than "these two statutes conflict as a matter of law." The tool knows nothing of severability, amendment, repeal, standing, or remedy.

Running it

Python 3.10+ and the Lean 4 toolchain (elan, providing lean/lake). No pip install is needed for the verification path.

git clone https://github.com/mehdievaltimes/legalean
cd legalean
python3 check_conflicts.py

Expected output: 23 rules loaded, 12 candidates checked, 12 formally verified conflicts — six contradictions and six field preemptions. CI runs exactly this on every push, installing Lean from scratch, so the build badge reflects proofs that compile on a clean machine rather than on one developer's laptop.
